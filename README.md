# 세움 · seum-tax-kr

상속·증여·양도 세무 검토를 위한 모바일 웹 앱입니다. 고객은 설치나 로그인 없이 이용하고, 전문가 검토 화면은 담당자 인증으로 보호합니다.

[앱 바로가기](https://seum-tax-kr.kbj060813.chatgpt.site)

## 세 기능의 역할

| 기능 | OpenAI·RAG 역할 | 코드·공식 데이터 역할 |
| --- | --- | --- |
| 세액 계산 | 상황·공제 조건 검토, 사실관계 추가 질문, 출처가 있는 계산 입력 초안 | 사용자가 확인한 입력을 서버에서 정수 원 단위로 계산 |
| 판례·쟁점 | 쟁점 분류, 관련 원문 검색, 우리 사례와 공통점·차이·적용 시점 비교 | 국세청 공개 검색, 사건번호·원문 식별자·법령 버전 대조 |
| AI 컨설팅 | 후속 대화를 이어받아 근거와 권장 행동 안내 | 서버 대화 이력·인용 검증·전문가 검토 기록 |

AI는 산출세액을 임의 생성하지 않습니다. 세액 화면에서 제안 금액을 확인·수정하고 계산 가정에 동의해야 계산합니다. 고객이 명시한 금액은 원문 표현과 단위를 코드로 대조하며, 확인하지 못한 값은 비워 둡니다. 최종 확인한 계산 시나리오는 해당 검토 기록에 저장합니다.

## 공식 자료와 RAG

국세청 국세법령정보시스템의 공개 검색·상세 화면이 사용하는 읽기 전용 요청을 직접 호출합니다. 법령·시행령·시행규칙, 예규·해석례, 법원 판례·행정 결정례를 구분합니다. 법령 연혁에서 거래 기준일의 버전을 선택하고, 조문에 속한 항·호를 연결해 읽습니다.

검색 목록 요약과 실제 확보한 본문을 구별합니다. 원문에 연결된 조문을 추가 조회하고, OpenAI가 사례 관련성을 평가한 뒤 실제 근거 ID로만 답변하도록 검증합니다. 기존 Vector Store 색인도 함께 검색합니다.

- 쟁점 지도: 24개 탐색 분류. 정답이나 판례를 대신하는 고정 답변 목록이 아닙니다.
- 초기 벡터 색인: 공식 자료 5건. 국세청 전체 자료를 벡터 DB에 복제한 것은 아닙니다.
- 공식 검색 캐시: 목록 15분, 상세 본문 6시간.
- 검색·원문 조회가 실패하면 누락을 표시하고 검토를 제한합니다.
- 전체 세법·판례의 완전성, 최신성, 검색 순위의 법적 정확성을 보증하지 않습니다.

## 전문가 검토

자료 충돌, 불명확한 사실관계, 법령 적용 시점, 판결 확정 상태, 근거 부족 등을 별도 검토란에 남깁니다. 고객용 검토 현황과 담당자용 `/expert` 화면을 구분합니다.

담당자는 질문·AI 안내·비교 근거·계산 입력 초안·확인된 계산 결과를 보고, 내부 메모와 고객 전달 의견을 별도로 작성합니다. 내부 메모는 고객 API에 포함하지 않습니다. 완료 처리에는 담당자의 명시적 확인이 필요하며 동시 수정은 버전으로 검사합니다.

## 계산 범위

현재 계산 코드는 **2026년 일반 기본세율 시나리오**를 지원합니다.

- 상속·증여: 입력한 재산가액, 채무 등 차감액, 합산 사전증여액, 공제 합계액으로 과세표준과 산출세액 계산.
- 양도: 양도가액, 취득가액, 필요경비, 사용자가 확인한 장기보유특별공제액과 기본공제 잔여액을 적용.
- 세액공제, 세대생략 할증, 중과·단기보유 등 별도 세율, 비과세·감면, 가산세 및 특례를 자동 확정하지 않습니다.
- 양도 지방소득세 표시는 국세 산출액의 10% 단순 추정입니다.
- 계산 결과는 신고 납부세액 확정이나 전문가 승인 의견이 아닙니다.

세율 기준: [국세청 상속세 항목별 설명](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7957&mi=6529), [국세청 양도소득세 세율](https://b.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7711&mi=2312).

## 기술 구조

브라우저 HTML/CSS/JavaScript → Worker ESM API → D1(SQLite) 저장소 + OpenAI Responses API/Vector Store + 국세청 공식 자료.

- `public/`: 모바일 웹 UI, 챗봇, AI 세액 입력, 비교 분석, 전문가 화면.
- `worker/`: API, RAG 검색, 인용 검증, 세액 계산.
- `data/`: 쟁점 분류와 초기 공식 원문·색인 메타데이터.
- `db/`, `drizzle/`: 스키마와 배포 마이그레이션.
- `tests/`: 계산 경계값, 금액 단위, 인용·소유권·개인정보 분리, 대화·검토 흐름.

## 로컬 실행

Node.js 24 이상과 npm이 필요합니다.

```bash
npm ci
npm run build
npm test
npm run dev
```

기본 미리보기는 `http://127.0.0.1:5190`입니다. 기본 실행은 계정의 API 키를 자동 사용하지 않습니다. AI를 실제 실행하려면 무시되는 `.env.local`에 본인 키를 설정하고, `SEUM_USE_ENV_FILE=1`을 명시해 실행합니다. 이 파일은 공유·커밋하지 마세요.

```powershell
$env:SEUM_USE_ENV_FILE = '1'
npm run dev
```

로컬 실시간 검색에는 `.env.local`의 `SEUM_LIVE_RESEARCH=true`를 사용합니다. 새 계정에서는 원문을 별도 색인하거나 실시간 검색을 이용해야 하며, 다른 계정의 Vector Store ID를 그대로 사용할 수 없습니다.

## 운영 환경 변수

| 이름 | 용도 |
| --- | --- |
| `OPENAI_API_KEY` | 서버 비밀값. 브라우저에 제공하지 않음 |
| `OPENAI_MODEL` | 기본 `gpt-4.1-mini` |
| `OPENAI_ORGANIZATION` | 키가 발급된 조직. 필요한 경우 명시 |
| `SEUM_LIVE_RESEARCH` | `true`이면 국세청 공개 검색 활성화 |
| `OPENAI_VECTOR_STORE_ID` | 선택한 검색 저장소. 없으면 기존 D1 설정 확인 |
| `EXPERT_EMAILS` | 담당자 이메일 허용 목록. 서버 비밀값으로 관리 |
| `DB` | Sites D1 바인딩 |

Sites의 보안 환경변수로 비밀값을 설정합니다. 저장소·배포 manifest·README에는 실제 API 키를 넣지 않습니다. 고객 연락처는 모델에 전송하지 않습니다. 고객 질문은 AI에 전달되며, 공식 검색에는 개인정보를 제외한 쟁점 검색어를 사용하도록 처리합니다.

## 검증과 배포

`npm run build`와 `npm test`를 실행합니다. Windows의 설치된 Chrome을 사용하는 UI 검증은 다음과 같습니다. UI 검증의 모델 응답은 테스트 문구로 명시한 모의 데이터이며, 실제 API 검증과 구분합니다.

```bash
node tests/browser-chat.mjs
node tests/browser-research.mjs
node tests/browser-workspace.mjs
```

GitHub Actions는 Node.js 24에서 설치·빌드·서버 테스트를 실행합니다. `.env.local`, 고객 상담 DB, `.local/`, 로그와 배포 출력은 Git에서 제외합니다.

운영 배포는 `.openai/hosting.json`의 기존 Sites 프로젝트를 유지하고, 소스 동기화 → 빌드·검증 → 산출물 저장 → 버전 배포 순서로 진행합니다. DB 마이그레이션은 배포 과정에서 적용합니다. 전문가 인증은 Sites가 주입하는 사용자 ID·이메일과 서버 허용 목록을 대조하며, 공개 사이트의 고객 이용에는 로그인을 요구하지 않습니다.

## 운영상 남은 범위

원문 사이트의 응답 구조 변경에 대한 점검이 필요합니다. 이메일·문자 알림, 고객 계정 복구, 자동 신고·납부, 전문가 자동 배정, 운영용 데이터 보존·삭제 UI는 제공하지 않습니다. 실제 서비스의 개인정보 처리방침·보유기간·담당 전문가 운영 체계는 운영자가 확정해야 합니다.
